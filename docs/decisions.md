### F1 (renderer + kiosk)
- 2026-11-24 · API renderer: `<PageRenderer page config mode runtime onAction resolveAssetUrl fit />`; `fit="contain"` (Kiosk, letterbox) atau `fit="none"` (ukuran artboard, editor yang mengatur zoom). Setiap elemen dibungkus `data-pb-element-id`/`data-pb-element-type`; di mode `editor` isi elemen `pointer-events: none` agar klik jatuh ke kotak elemen (target `react-moveable`/`selecto` di F2). `RendererProvider`, `ElementView`, `FrameComposite`, `FilteredImage` juga diekspor · Studio F2 memakai renderer yang sama tanpa fork.
- 2026-11-24 · Semua data elemen khusus lewat satu objek `runtime` (opsional per field); tanpa data → placeholder berlabel (editor) atau kotak netral tanpa teks (live) · Kiosk tidak boleh menampilkan teks yang bukan dari desain owner.
- 2026-11-24 · Tombol yang aksinya tidak berlaku saat ini (mis. "Selesai" selama countdown) tampil redup dan tidak bereaksi; Kiosk menentukannya dengan `snapshot.can(event)` dari flow machine · satu sumber kebenaran untuk aturan flow.
- 2026-11-24 · Filter = satu transformasi warna afin (matriks 3×3 + offset, urutan brightness → contrast → saturation → hueRotate → sepia → warmth, matriks saturate/hue-rotate/sepia dari spesifikasi Filter Effects) + overlay vignette/grain. Definisi di `@pb/schema` (`filterColorMatrix`, `VIGNETTE_INNER`, `GRAIN_OPACITY`); renderer menerapkannya dengan SVG `feColorMatrix` (`filter: url(#…)`, sRGB) · CSS `filter` bawaan meng-clamp di setiap langkah dan tidak punya warmth; satu matriks bisa ditiru persis oleh `sharp` (`recomb` + `linear`) di F3.
- 2026-11-24 · Format `admin.pinHash`: `pbkdf2-sha256$<iterasi>$<salt b64url>$<hash b64url>` (210.000 iterasi, Web Crypto) dengan `hashAdminPin`/`verifyAdminPin` di `@pb/schema`; zod menerima `''` atau format ini. Tanpa kenaikan `schemaVersion` · semua config tersimpan masih `''` sehingga tetap valid; Studio (Node) dan Kiosk (browser) memakai kode yang sama. Kiosk mengunci PIN 60 dtk setelah 5 kali salah.
- 2026-11-24 · `autoAdvanceBetweenShots` hanya berlaku *antar* foto. Setelah foto terakhir, Capture menunggu tombol `next`/`confirm` (agar retake masih bisa); jika halaman tidak punya tombol itu, lanjut otomatis setelah 3 dtk · menjaga aturan validasi "Capture = next/confirm atau autoAdvance" tetap punya jalan keluar.
- 2026-11-24 · Sesi berbayar tidak pernah dibuang: idle setelah lunas melanjutkan sesi (Capture → foto berikutnya/Review, Review → konfirmasi), dan keluar dari halaman Error (tombol apa pun atau idle) melanjutkan Capture/Processing, bukan Cover. Sebelum lunas, idle → Cover dan QRIS dibatalkan · PRD §6 "timeout tidak menghapus sesi".
- 2026-11-24 · QRIS kedaluwarsa → batalkan dan kembali ke Pilih Frame (bukan membuat QR baru otomatis) · QR hanya dibuat saat pembeli aktif (biaya provider).
- 2026-11-24 · Idle timer ada di flow machine (`raise` tertunda dengan id, di-reset di setiap halaman dan event `ACTIVITY`); Kiosk mengirim `ACTIVITY` di setiap sentuhan · perilaku sama di Kiosk dan preview Studio.
- 2026-11-24 · Mode admin hanya bisa dibuka saat tidak ada sesi berbayar; menu F1: tes kamera, sesi gratis, sesi tersimpan, muat ulang config, layar penuh. Gesture: 5 ketukan di 100×100 px kiri atas dalam 3 dtk · UI admin adalah UI sistem operator (bukan desain owner), teks Bahasa Indonesia.
- 2026-11-24 · `CaptureSource` ditambah `lastError()`, `onStatusChange()` dan status `idle` · Kiosk perlu tahu saat webcam dicabut (event `ended` track) untuk membawa flow ke Error.
- 2026-11-24 · Foto di slot dan pratinjau ditampilkan ter-mirror bila `camera-view.mirror` (sesuai yang dilihat pembeli); file original tetap tanpa mirror · PRD §8 (`mirrored/` = yang dilihat pembeli).
- 2026-11-24 · Config Kiosk di F1: file JSON lokal disajikan plugin Vite di `/booth-config.json` (`apps/kiosk/booth-config.local.json`, gitignored, dibuat dari `createDefaultBoothConfig()` dengan PIN admin dev `1234`; `PB_KIOSK_CONFIG` / `?config=` untuk file lain). Config tidak valid → layar sistem berisi daftar masalah, coba lagi otomatis · F2 mengganti sumbernya dengan API/agent.
- 2026-11-24 · Hasil sesi F1 disimpan di IndexedDB (`pb-kiosk`: metadata + semua take, termasuk yang di-retake) dan bisa diunduh dari mode admin; tidak ada penghapusan otomatis · invarian "hapus hanya setelah upload terkonfirmasi"; F3 memindahkan ini ke agent.
- 2026-11-24 · Error render → event `FAIL` → halaman Error desain owner; jika halaman Error sendiri gagal dirender → layar sistem dan reload otomatis 30 dtk · tidak pernah layar putih.
- 2026-11-24 · Pengerasan kiosk di browser (layar penuh pada sentuhan pertama, kursor disembunyikan, blokir menu konteks) aktif di build produksi atau `?kiosk=1`; Wake Lock selalu diminta. Pembungkus Tauri ditunda ke F3 bersama agent sidecar · F1 hanya mensyaratkan browser; Tauri menambah toolchain Rust tanpa nilai sebelum ada agent.
- 2026-11-24 · `voucher-input` di F1 hanya visual; input dan validasi voucher di F4 · di luar cakupan F1.

### F2 (Studio editor + publish + pairing) — rencana arsitektur editor
Ditulis sebelum implementasi F2; penyimpangan selama implementasi dicatat di bawahnya.

- 2026-11-24 · **State editor**: satu `EditorStore` (kelas kecil + `useSyncExternalStore`, tanpa library state tambahan) di `apps/studio/src/editor/`. Dua bagian: (1) *dokumen* = seluruh `BoothConfig` draft (satu-satunya data yang disimpan dan di-undo); (2) *UI state* = target edit (halaman / slide Tutorial / frame), seleksi, zoom/pan, clipboard, tab panel — tidak masuk riwayat. Komponen membaca lewat selector (`useEditor(s => …)`) agar panel tidak ikut render ulang saat drag · satu sumber kebenaran; config yang dipublish = dokumen editor apa adanya.
- 2026-11-24 · **Undo/redo**: setiap perubahan dokumen lewat `store.apply(label, recipe)` = Immer `produceWithPatches`; entri riwayat = `{patches, inversePatches, label, selectionBefore, selectionAfter}`, maksimal 200 entri (≥ 100 sesuai F2). Undo menerapkan inverse patches dan memulihkan seleksi. Perubahan beruntun dengan `coalesceKey` yang sama dalam 600 ms (nudge keyboard, ketik di panel) digabung jadi satu entri. Tidak ada mutasi dokumen di luar `apply` · pola patch lebih hemat memori daripada snapshot config penuh dan mudah diuji.
- 2026-11-24 · **Lapisan interaksi**: canvas = viewport (zoom/pan) → stage `transform: translate() scale(zoom)` → `<PageRenderer fit="none" mode="editor">` (renderer yang sama dengan Kiosk) → overlay `react-moveable` (drag/resize/rotate/snap/guide, grup multi-seleksi) + `react-selecto` (klik, shift-klik, kotak seleksi). Target Moveable adalah kotak `[data-pb-element-id]` yang sudah dirender renderer; editor tidak menggambar ulang elemen · WYSIWYG terjamin karena canvas *adalah* renderer.
- 2026-11-24 · **Sinkron dengan renderer**: selama gesture, Moveable mengubah style DOM secara langsung (tanpa render React, tetap 60 fps); di akhir gesture satu `apply()` menulis x/y/width/height/rotation (px artboard, dibulatkan 0,1) ke dokumen, lalu renderer merender ulang dari dokumen dan style sementara dikembalikan ke nilai dokumen (juga saat gesture dibatalkan / tanpa perubahan). Koordinat dari Moveable sudah dalam px artboard karena dihitung relatif terhadap parent yang di-scale; `zoom` hanya memengaruhi ukuran handle.
- 2026-11-24 · **Snap & guide**: fitur `snappable` Moveable — garis tepi/tengah artboard, elemen lain (`elementGuidelines`), grid (`snapGridWidth/Height`, default 20 px, bisa dimatikan); garis guide dan jarak ditampilkan Moveable.
- 2026-11-24 · **Model elemen di editor**: target edit `page` (elemen halaman), `slide` (Tutorial: elemen slide + elemen halaman; elemen statis baru masuk slide, tombol masuk halaman) dan `frame` (canvas 600×1800 dari `FrameComposite`, slot = kotak `[data-pb-frame-slot]`, elemen dinamis = `ElementView`). Group = elemen dengan `groupId` sama; klik satu anggota memilih seluruh grup. Lock = tidak bisa dipilih/digeser di canvas (tetap bisa dari layer panel). Hide = `visible:false` (renderer tidak menggambar). Urutan layer = urutan array.
- 2026-11-24 · **Panel properti**: deskriptor field per tipe elemen (geometri, `BoxStyle`, `TextStyle`, lalu field khusus tipe) dirender oleh satu komponen generik; satu field = satu `apply()` saat commit (blur/Enter/slider dilepas). Panel "Tambah elemen" hanya menawarkan tipe yang boleh di halaman aktif (`ELEMENT_ALLOWED_PAGES`).
- 2026-11-24 · **Validasi & autosave**: `validateBoothConfig` dijalankan (debounce 300 ms) pada dokumen; masalah dikelompokkan per halaman/frame, klik masalah memilih elemen terkait. Autosave draft ke `booth_drafts` lewat server action 1 dtk setelah perubahan terakhir (RLS, last-write-wins), status "Menyimpan/Tersimpan/Gagal" di toolbar.
- 2026-11-24 · **Aset**: upload lewat route handler Studio → hitung sha256 + ukuran di server → simpan file lewat `AssetStorage` (dev: disk lokal `.data/assets`, disajikan Studio di `/media/…`; Supabase Storage bucket publik di mode supabase) → baris `assets` (RLS). Saat aset dipakai, `AssetRef` ditambahkan ke `config.assets` dalam entri riwayat yang sama; saat publish aset yang tidak direferensikan dibuang. Font: family `pb-font-<assetId>`, renderer memasang `@font-face` untuk aset font.
- 2026-11-24 · **Publish/versi**: publish = validasi ulang di server → transaksi: versi = max+1, `configVersion` = versi, insert `booth_configs` (immutable), set `booths.active_config_id`, audit log, `pg_notify('pb_booth_config', boothId)`. Rollback = publish versi baru berisi config versi lama ("rollback dari vN") — versi selalu naik, riwayat tetap utuh, device cukup mengikuti "versi aktif berubah".
- 2026-11-24 · **Device**: pairing — Kiosk membuat token device acak sendiri, mengirim sha256-nya ke `POST /pair/start` dan menampilkan kode 6 digit; owner memasukkan kode di Studio → Studio memanggil API (`/studio/pairing/claim`, token user) → API membuat baris `devices` dengan hash tersebut. Token asli tidak pernah melewati server atau DB. Update config: API mendengarkan `pb_booth_config` (LISTEN) dan mendorong event lewat stream SSE `/device/stream` + polling `/device/config` (ETag) tiap 5 dtk sebagai cadangan → < 10 dtk. Kiosk mengunduh semua aset (Cache Storage, cek sha256) sebelum mengaktifkan versi baru; gagal → tetap versi lama. Agent mengambil alih caching ini di F3.

### F3 (Camera App + Local Agent + cetak 2×6)
- 2026-11-24 · Agent = Node 24 (Hono + `ws`) dengan SQLite bawaan `node:sqlite` · tanpa modul native SQLite (pnpm 12 memblokir build script); satu runtime Node juga menjalankan `sharp`. Port tetap: API Kiosk `127.0.0.1:47810`, server kamera LAN `0.0.0.0:47811`.
- 2026-11-24 · Pairing, token device, sinkron config + cache aset dipindah dari Kiosk ke agent (`apps/kiosk/src/remote/*` dihapus). Token device = file `device-token` (0600) di folder data agent, bukan keychain OS · keychain butuh modul native atau perintah Tauri; ditunda (open-questions #20). Kiosk `?source=api` tetap diterima sebagai alias `agent`. Mode admin punya **Lepas dari booth** (`POST /device/reset`) untuk pairing ulang; sesi di disk tetap.
- 2026-11-24 · API lokal agent dilindungi pengecekan `Host` (hanya `127.0.0.1`/`localhost`, anti DNS rebinding) + daftar `Origin` (Tauri + dev server Kiosk); permintaan tanpa Origin (proses lokal) diizinkan · halaman web lain di laptop tidak bisa memakai agent; proses lokal sudah punya akses mesin.
- 2026-11-24 · Server LAN kamera memakai HTTP/WS polos + token kamera (kode QR sekali pakai 10 menit → token 256-bit, disimpan sebagai sha256) · TLS di LAN butuh sertifikat self-signed + pinning di QR; ditunda (open-questions #21). iOS: `NSAllowsLocalNetworking`; Android: `allowMixedContent` + cleartext.
- 2026-11-24 · Kiosk = penerima WebRTC (offer `recvonly`), tablet = pengirim; agent hanya me-relay signaling, media peer-to-peer di LAN tanpa STUN · negosiasi ulang selalu dimulai Kiosk saat agent melaporkan `connectionId` baru, jadi tidak pernah ada negosiasi dari dua arah.
- 2026-11-24 · Deteksi Wi-Fi tablet putus: agent ping tiap 2 dtk dan memutus socket tanpa pong 5 dtk; tablet menutup socket bila tidak menerima pesan 6 dtk lalu reconnect cepat (300 ms → 3 dtk). Kiosk menampilkan banner sistem "Kamera terputus — menyambungkan ulang…" selama status `reconnecting` (bukan halaman Error); baru `error` (→ halaman Error desain owner) setelah 60 dtk · putus singkat tidak membuang pembeli ke halaman Error.
- 2026-11-24 · Foto tidak pernah hilang saat putus: permintaan capture di agent menunggu ≤ 60 dtk dan dikirim ulang saat tablet kembali (kecuali tablet melaporkan sudah memegang fotonya); tablet menyimpan foto di IndexedDB sampai agent membalas 200; upload idempotent per `requestId`; upload yang datang setelah timeout tetap disimpan sebagai take slot itu.
- 2026-11-24 · Foto resolusi penuh di tablet: `ImageCapture.takePhoto` pada ukuran maksimum sensor (Android/Chromium); bila tidak ada (iOS) plugin `@capacitor-community/camera-preview` — track preview dilepas, foto native diambil, preview dinyalakan lagi (`replaceTrack`, tanpa negosiasi ulang). Preview di Kiosk membeku ±1–2 dtk saat foto iOS diambil · kamera iOS tidak bisa dipakai dua sesi sekaligus; momen itu tertutup flash/pratinjau foto. Fallback frame dari stream hanya untuk browser tanpa keduanya dan ditandai `stream-frame`.
- 2026-11-24 · Compositor: `sharp` untuk decode (orientasi EXIF), mirror, crop tengah (object-fit cover), resize lanczos3 dan encode (JPEG q95 4:4:4 / PNG, 300 dpi); `@napi-rs/canvas` (Skia, mesin gambar yang sama dengan Chromium) untuk menyusun lapisan dan menggambar elemen dinamis (teks `pre-wrap` + half-leading CSS, shape, image, QR) · teks `sharp`/pango dipotong ke ink extents sehingga posisi baseline hilang.
